# FlareSolverr directory scanning

Manual season/keyword scans can optionally read ANI directory listings through a
FlareSolverr browser session. RSS updates keep their existing HTTP behavior.

Merge this into your existing configuration (keep your Openlist settings):

```yaml
ani:
  rss_update: false
  year: 2026
  month: 10
  src_domain: "openani.an-i.workers.dev"
  flaresolverr_url: "http://127.0.0.1:8191"
  flaresolverr_timeout: 60000
  resource_domain: "resources.ani.rip"
```

The Web UI exposes the new settings too. `flaresolverr_url` accepts the service
base URL or `/v1` endpoint. Leave it empty to retain direct requests. The timeout
is in milliseconds; the HTTP client allows an additional 15 seconds.
For separate containers on one Docker network, use `http://flaresolverr:8191`
(the service name), not `127.0.0.1`. Run FlareSolverr separately; this integration
does not install it or change Docker services. Keep its endpoint private.

Each scan creates a unique browser session, visits the source homepage, and then
posts each directory request through that session. The session is destroyed on
success or failure. Cookies are not exported to HTTP clients or persisted in
configuration. No new Python dependencies are required.

`resource_domain` changes only download links generated by manual scans. It is a
hostname without a scheme/path. If empty, links retain the source hostname and
may still require browser verification. FlareSolverr obtains directory metadata;
it does not proxy playback or provide clearance to Openlist clients. Existing
stored links and RSS-mode links are not rewritten.

## Compatibility and verification

The source must implement the existing ANI POST directory protocol (`files`
containing the same metadata fields used by the direct scanner). FlareSolverr's
`request.post` uses form submissions, not arbitrary JSON request bodies. This
adapter sends an empty form for directory listings. If the source requires JSON
or challenge handling loses the POST method, validation fails rather than
reporting an empty successful scan.

The adapter accepts raw JSON or JSON wrapped by Chromium in an HTML `pre` element.
It rejects challenge pages, non-200 solution status, and missing/non-list `files`.
Some FlareSolverr versions report synthetic HTTP 200, so body validation is needed.
FlareSolverr cannot guarantee that every challenge can be solved.

Tests mock FlareSolverr and do not access Openlist. Real ANI compatibility remains
unverified until tested with your FlareSolverr service. To check directory reading
without updating Openlist storage:

```python
import asyncio
from ani2openlist import Ani2Openlist, load_config
from ani2openlist.utils.http import RequestUtils

async def check():
    try:
        scanner = Ani2Openlist(config=load_config("config.yaml"))
        tree = {}
        await scanner.update_season_anime_dict(tree)
        print("Scanned season keys:", list(tree))
    finally:
        await RequestUtils.close_all_async_clients()

asyncio.run(check())
```

This calls only the directory scanner, not `run()` or the Openlist storage update.
Use a small known season first and inspect representative file links before a real
mount update.
